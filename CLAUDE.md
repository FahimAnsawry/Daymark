# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Daymark is a calm daily-planning product. It's a monorepo with two independent apps:

- `backend/`: a Laravel (PHP 8.5) JSON API using Sanctum bearer tokens, Socialite OAuth and PostgreSQL. **`backend/CLAUDE.md` holds the Laravel Boost guidelines (Pint, PHPUnit, artisan `make:` conventions, Boost MCP tools). Follow it for any backend work.**
- `frontend/`: a React 19 + TypeScript SPA built with Vite, TanStack Router (file-based), TanStack Query, Tailwind CSS v4, react-hook-form + zod, and lucide-react. Bun is the package manager (`bun.lock`).

`PRODUCT.md` (product scope and voice) and `DESIGN.md` (visual system: palette, typography, layout, motion) describe the product. Read them before UI or copy changes. Don't invent product features, pricing claims or testimonials that aren't already there.

## Commands

Root helpers are in `package.json` (`bun run dev`, `bun run dev:backend`, `bun run build:frontend`, `bun run format`, `bun run migrate:backend`).

Backend (run from `backend/`):
- `php artisan serve` starts the API on http://127.0.0.1:8000
- `php artisan migrate`
- `php artisan test --compact` runs all tests; add `--filter=testName` to run one
- `vendor/bin/pint --dirty --format agent` formats changed PHP (required after PHP edits)

Frontend (run from `frontend/`):
- `bun run dev` starts Vite on http://localhost:5173. It proxies `/api`, `/auth` and `/sanctum` to :8000.
- `bun run build` runs `tsc -b` and then `vite build` (this is the type check)
- `bun run lint` runs oxlint
- `bun run format` / `bun run format:check` runs Prettier (no semicolons, single quotes; see `.prettierrc`)
- `node --test tests/` runs the unit tests.
- `node scripts/verify-navbar.mjs` and `scripts/verify-footer.mjs` are regex assertions over component and CSS source. They break if you rename the class names, ids or aria attributes they check.

## Architecture

**Auth flow.** The backend issues Sanctum personal access tokens from `/api/auth/register`, `/login` and the OAuth callbacks. The frontend keeps the token in `localStorage['auth_token']`. The axios instance in `frontend/src/lib/api.ts` attaches it as a Bearer header and clears it on any 401. `frontend/src/lib/auth-context.tsx` exposes `useAuth()`, backed by a TanStack Query on `['auth','user']` that calls `/auth/me`. OAuth (Google/GitHub) uses stateless Socialite in `AuthController`. The callback redirects back to `FRONTEND_URL` with the token. Linked login methods are stored as `Account` rows (`provider` = `password` | `google` | `github`) that belong to `User`.

**API conventions.** All endpoints live in `backend/routes/api.php`, and controllers are under `app/Http/Controllers/Api`. Responses go through Eloquent API Resources in `app/Http/Resources`. The API has no versioning prefix.

**Tasks.** Dashboard tasks and projects (`routes/dashboard.tsx`) are **client-only**: they're saved to `localStorage` per user and aren't stored on the backend. `/api/tasks` (`DemoTaskController`) is a leftover in-memory demo, not a real persistence layer.

**Frontend routing.** Routes are files in `frontend/src/routes/` (`__root.tsx` is the layout). `routeTree.gen.ts` is generated by the TanStack Router Vite plugin, so never edit it by hand. The `@` alias points to `frontend/src`. The theme (light/dark/system) comes from `lib/theme.tsx`. Styling uses Tailwind v4 via `src/index.css` (there's no `tailwind.config`).

**Testing DB.** `phpunit.xml` runs backend tests against in-memory SQLite, while dev uses PostgreSQL. Avoid Postgres-only SQL in code that tests exercise.
